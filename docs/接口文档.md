## 一、通用约定

### 1.1 Base URL

```
http://localhost:8080/api
```

Vite 开发环境通过 `server.proxy` 将 `/api` 代理到该地址，前端 Axios 的 `baseURL` 统一写 `/api`，由拦截器完成 `Result<T>` 解包与错误提示。

### 1.2 请求约定

| 项目 | 约定 |
| --- | --- |
| 报文格式 | `application/json;charset=UTF-8`（GET 使用 Query 参数） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 金额单位 | 整数「分」，字段以 `Cents` 结尾（如 `priceCents`）；严禁 `float` / `double`；数据库 `DECIMAL(10,2)` 的元值由 Service 层换算，前端展示时除以 100 |
| 分页请求 | `pageNum`（从 1 开始，默认 1）、`pageSize`（默认 10，最大 50） |
| 认证方式 | 请求头 `Authorization: Bearer {token}` |

### 1.3 统一响应结构 `Result<T>`

所有接口（成功与失败）统一返回 `Result<T>`，禁止裸露数据、裸 VO、裸 `Map`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { },
  "timestamp": 1761700000000
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 业务状态码，见 1.4 |
| message | string | 中文提示信息，可直接展示给用户 |
| data | T | 业务数据载荷，无数据时为 `null` |
| timestamp | long | 响应生成时间戳（毫秒） |

分页数据放在 `data` 中，遵循 PageHelper `PageInfo` 结构：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "list": [],
    "total": 12,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 2
  },
  "timestamp": 1761700000000
}
```

### 1.4 业务状态码

HTTP 状态码与 `code` 保持一致，前端统一以响应体 `code` 判定结果。

| code | 名称 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| 200 | SUCCESS | 成功 | 正常返回 |
| 400 | PARAM_ERROR | 参数校验失败 | 用户名为空、评分越界、缺少收货地址 |
| 401 | UNAUTHORIZED | 未登录 / 登录态失效 | 未带 Token、Token 已登出 |
| 403 | FORBIDDEN | 无权限 | 普通用户访问后台、访问他人订单 |
| 404 | NOT_FOUND | 资源不存在 | 商品、订单、购物车项不存在 |
| 409 | STATUS_CONFLICT | 状态不允许 | 订单流转非法、重复评价、商品已下架 |
| 422 | STOCK_NOT_ENOUGH | 库存不足 / 数量不合法 | 加购或下单超过库存 |
| 500 | SERVER_ERROR | 服务器内部错误 | 未捕获异常 |

### 1.5 枚举约定

**用户角色 `role`**：`0` 管理员，`1` 普通用户
**商品状态 `status`**：`0` 已下架，`1` 已上架
**订单状态 `status`**：`0` 待支付，`1` 已支付，`2` 已发货，`3` 已完成，`4` 已取消

订单状态流转：

```
0 待支付 --付款--> 1 已支付 --管理员发货--> 2 已发货 --用户确认收货--> 3 已完成(终态)
0 待支付 --用户取消--> 4 已取消(终态)
```

### 1.6 认证与权限

- 登录成功返回 `token`，服务端以 Token 为键保存登录态；登出即销毁，旧 Token 请求返回 `401`。
- `/admin/**` 仅 `role=0` 可访问，否则 `403`。
- 用户类接口（购物车、订单、评价）只操作 Token 对应的当前用户数据，服务端不接收、不信任前端传入的 `userId`；按主键操作时必须校验归属，越权返回 `403`。

## 三、认证模块

### A1 注册 `POST /auth/register`

```json
{
  "username": "user3",
  "password": "123456"
}
```

| 字段 | 类型 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| username | string | 是 | `@NotBlank` `@Size(min=3,max=50)`，全局唯一 |
| password | string | 是 | `@NotBlank` `@Size(min=6,max=32)`，服务端 MD5 后入库 |

`data`：

```json
{ "id": 4, "username": "user3", "role": 1 }
```

失败：`400` 参数不合法；`409` 用户名已存在（`用户名已被注册`）。
请求体中的 `role` 一律忽略，注册固定创建 `role=1`。

### A2 登录 `POST /auth/login`

```json
{ "username": "user1", "password": "123456" }
```

`data`：

```json
{
  "token": "8f3c1d2e-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "user": { "id": 2, "username": "user1", "role": 1 }
}
```

失败：`400` 参数缺失；`401` 用户名或密码错误。
前端将 `token` 存入 localStorage，请求时放入 `Authorization` 头，刷新页面登录态不丢失。

### A3 登出 `POST /auth/logout`

`data` 为 `null`。服务端销毁 Token，之后携带旧 Token 的请求返回 `401`。

### A4 当前登录信息 `GET /auth/me`

```json
{ "id": 2, "username": "user1", "role": 1 }
```

## 五、购物车模块（需登录）

**购物车行对象**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | long | 购物车行 ID |
| productId | long | 商品 ID |
| productName | string | 商品名称 |
| priceCents | int | 当前单价（分），仅展示，下单金额由服务端重算 |
| quantity | int | 数量 |
| stock | int | 商品当前库存 |
| imageUrl | string | 图片地址 |
| available | boolean | 是否可结算（上架且库存足够） |
| invalidReason | string | `OFF_SHELF` / `OUT_OF_STOCK` / `null` |

### D1 购物车列表 `GET /cart`

```json
{
  "items": [
    {
      "id": 5,
      "productId": 2,
      "productName": "得力 2B铅笔 10支装",
      "priceCents": 800,
      "quantity": 2,
      "stock": 200,
      "imageUrl": "/img/pencil.jpg",
      "available": true,
      "invalidReason": null
    }
  ],
  "totalAmountCents": 1600,
  "totalQuantity": 2
}
```

`totalAmountCents` 只统计 `available=true` 的行。

### D2 加入购物车 `POST /cart`

```json
{ "productId": 2, "quantity": 1 }
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| productId | long | 是 | `@NotNull` |
| quantity | int | 是 | `@Min(1)` |

同一用户同一商品只保留一行（唯一索引 `uk_user_product`），重复加入按原行累加数量。
`data`：该购物车行对象。
失败：`404` 商品不存在；`409` 商品已下架；`422` 累加后超过库存（`库存不足，当前库存 200`）。

### D3 修改数量 `PUT /cart/{id}`

```json
{ "quantity": 3 }
```

`data`：更新后的购物车行。失败：`403` 该行不属于当前用户；`404` 行不存在；`422` 超过库存。

### D4 删除单项 `DELETE /cart/{id}`

`data` 为 `null`。失败：`403` 越权；`404` 行不存在。

### D5 清空购物车 `DELETE /cart`

`data` 为 `null`，仅清空当前用户的行。

## 六、订单模块（用户，需登录）

**订单对象**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | long | 订单 ID |
| orderNo | string | 订单号 `ORD{yyyyMMddHHmmss}{4位随机}` |
| totalAmountCents | int | 订单总金额（分），服务端按当时单价计算 |
| status | int | 订单状态 |
| statusText | string | 待支付 / 已支付 / 已发货 / 已完成 / 已取消 |
| address | string | 收货地址 |
| createTime | string | 下单时间 |
| items | array | 订单明细 |

**订单明细对象**（保存下单时的名称与单价快照，商品改价不影响历史订单）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| productId | long | 商品 ID |
| productName | string | 下单时商品名称快照 |
| priceCents | int | 下单时单价快照（分） |
| quantity | int | 数量 |
| subtotalCents | int | `priceCents * quantity` |

### E1 结算下单 `POST /orders`

```json
{
  "cartItemIds": [5, 6],
  "address": "北京市海淀区中关村大街1号"
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| cartItemIds | long[] | 是 | `@NotEmpty`，元素 `@NotNull` |
| address | string | 是 | `@NotBlank` `@Size(max=255)` |

服务端处理（`@Transactional(rollbackFor = Exception.class)`，任一环节失败整体回滚）：

1. 校验每行购物车属于当前用户；
2. 校验商品均上架、数量不超过库存（整单校验，不允许生成不完整订单）；
3. 按当时单价计算 `totalAmountCents`，忽略前端传入的任何金额；
4. 扣库存 → 写订单 → 写订单明细（含名称、单价快照）；
5. 删除已结算的购物车行。

`data`：

```json
{
  "id": 6,
  "orderNo": "ORD202610291200001234",
  "totalAmountCents": 1600,
  "status": 0,
  "statusText": "待支付"
}
```

失败：`400` 未选择商品 / 地址为空；`403` 购物车行不属于当前用户；`404` 购物车行不存在；`409` 商品已下架；`422` 库存不足（提示具体商品名）。

### E2 我的订单列表 `GET /orders?status=0&pageNum=1&pageSize=10`

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| status | 否 | 订单状态；不传返回全部 |
| pageNum / pageSize | 否 | 分页 |

只返回当前用户订单，按 `createTime` 倒序，`data` 为分页结构，`list` 元素为订单对象（含 `items`）。

### E3 我的订单详情 `GET /orders/{orderNo}`

`data`：订单对象（含完整 `items`）。
失败：`404` 订单不存在；`403` 无权访问该订单。

### E4 模拟付款 `POST /orders/{orderNo}/pay`

仅 `status=0` 可付款 → `1`。`data` 为更新后的订单对象。
失败：`403` 非本人订单；`404` 不存在；`409` 当前订单状态不允许支付。

### E5 取消订单 `POST /orders/{orderNo}/cancel`

仅 `status=0` 可取消 → `4`，同一事务内回补库存。
失败：`403` 非本人；`409` 当前状态不允许取消。

### E6 确认收货 `POST /orders/{orderNo}/confirm`

仅 `status=2`（已发货）可确认 → `3`。已完成/已取消为终态，任何角色不可再改。
失败：`403` 非本人；`409` 当前状态不允许确认收货。

## 七、评价模块（需登录）

### F1 提交评价 `POST /reviews`

```json
{
  "orderId": 4,
  "productId": 8,
  "rating": 5,
  "content": "鼠标很好用，静音效果不错！"
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| orderId | long | 是 | `@NotNull` |
| productId | long | 是 | `@NotNull` |
| rating | int | 是 | `@Min(1)` `@Max(5)`（`评分必须在 1~5 之间`） |
| content | string | 是 | `@NotBlank` `@Size(max=500)` |

规则：订单必须属于当前用户且 `status=3`（已完成）；商品必须在该订单明细中；同一订单同一商品只能评价一次（唯一索引 `uk_order_product`）。
`data`：新增评价对象。
失败：`400` 评分/内容不合法；`403` 订单不属于当前用户；`404` 订单或商品不存在；`409` 订单未完成 / 已评价（`该商品已评价，请勿重复评价`）。

## 九、后台商品管理（仅管理员）

### H1 商品列表 `GET /admin/products?categoryId=4&status=0&pageNum=1&pageSize=10`

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| categoryId | 否 | 分类筛选（含一级分类） |
| status | 否 | `0` 已下架 / `1` 已上架；不传返回全部 |
| pageNum / pageSize | 否 | 分页 |

元素在前台字段基础上增加 `status`、`createTime`：

```json
{
  "id": 12,
  "name": "计算器 12位大屏",
  "priceCents": 4500,
  "stock": 40,
  "categoryId": 6,
  "categoryName": "文件管理",
  "imageUrl": "/img/calculator.jpg",
  "description": "下架测试商品",
  "status": 0,
  "createTime": "2023-10-01 10:00:00"
}
```

### H2 新增商品 `POST /admin/products`

```json
{
  "name": "钢笔 礼盒装",
  "priceCents": 6800,
  "stock": 30,
  "categoryId": 4,
  "description": "书写顺滑",
  "imageUrl": "/img/pen2.jpg",
  "status": 1
}
```

| 字段 | 类型 | 必填 | 校验 |
| --- | --- | --- | --- |
| name | string | 是 | `@NotBlank` `@Size(max=100)` |
| priceCents | int | 是 | `@NotNull` `@Min(1)`（单位分） |
| stock | int | 是 | `@NotNull` `@Min(0)` |
| categoryId | long | 是 | `@NotNull`，必须是已存在的二级分类 |
| description | string | 否 | `@Size(max=500)` |
| imageUrl | string | 否 | `@Size(max=255)` |
| status | int | 否 | 默认 `1`，仅允许 `0/1` |

失败：`400` 参数不合法；`404` 分类不存在。

### H3 编辑商品 `PUT /admin/products/{id}`

请求体同 H2（全量提交）。失败：`400` 参数不合法；`404` 商品不存在。
修改价格只影响新订单，历史订单使用明细快照。

### H4 上架 / 下架 `PUT /admin/products/{id}/status`

```json
{ "status": 0 }
```

`data`：更新后的商品对象。失败：`400` status 只能是 0 或 1；`404` 商品不存在。
下架后：前台列表/详情不可见、不可加入购物车；购物车旧行标记 `available=false`、`invalidReason=OFF_SHELF`，不可结算。

## 十二、实现约束

| 约束 | 说明 |
| --- | --- |
| 统一响应 | Controller 一律返回 `backend/src/main/java/com/example/backend/common/Result.java`，字段固定 `code / message / data / timestamp` |
| 入参校验 | 请求体 DTO 标注 `@Valid` + Jakarta Validation 中文提示，由全局异常处理器统一转 `400` |
| 不裸露实体 | MyBatis 实体不得直接出参，统一转为 VO（`ProductVO`、`OrderVO` 等） |
| 事务 | 下单（E1）、取消（E5）、发货（G3）等多表写操作使用 `@Transactional(rollbackFor = Exception.class)` |
| Mapper | 多表关联 / 动态条件写 XML，SQL 用 `#{}`，禁止 `${}` 与 `SELECT *` |
| 越权防护 | D3/D4、E3~E6、F1 在 Service 层校验数据归属当前用户 |
| 金额 | 接口与前端统一用分，Service 层在 `DECIMAL(10,2)` 与分之间换算，禁止浮点运算金额 |
